# 小智后端服务（xiaozhi-esp32-server）技术方案说明

> 本文档面向下一个接手本项目的 AI/开发者，目标是**只看这一篇就能理解本项目的整体方案、当前实际使用的 AI 组件（ASR / TTS / LLM / 意图识别 / 记忆等）以及数据流**。
>
> 项目位置：`E:\ESP32\my-server`
> 上游项目：<https://github.com/xinnan-tech/xiaozhi-esp32-server>（MIT 协议，华南理工大学刘思源教授团队主导）
> 配套硬件：<https://github.com/78/xiaozhi-esp32>

## 1. 一句话概述

这是一个为 **ESP32 智能语音硬件（"小智"）** 提供后端服务的开源系统。ESP32 设备通过 **WebSocket** 把麦克风采集的音频流发到后端，后端依次完成 **VAD → ASR → LLM → TTS** 的处理链路，再把合成好的语音送回设备播放，从而让硬件具备"听懂人话、回答问题、播报语音"的完整语音助手能力。

除了核心语音引擎，它还配套了 **Web 管理后台**（配置 AI 服务、管理用户/设备/音色/OTA）、**移动管理端**、以及一个**数字人测试模块**。

---

## 2. 整体架构

系统由 **5 个独立组件**组成，前后端分离、核心服务与管理服务分离：

```
xiaozhi-esp32-server
  ├─ xiaozhi-server    8000端口  Python       核心 AI 引擎，与 ESP32 通信，处理语音链路
  ├─ manager-web       8001端口  Vue 2        管理后台 Web 界面
  ├─ manager-api       8002端口  Java(Spring Boot)  管理后台后端 + 配置中心 + 数据库
  ├─ manager-mobile    跨平台    uni-app+Vue3 移动版智控台（Android/iOS/微信小程序）
  └─ digital-human     8006端口  Python+Web   数字人测试模块（本地测试页 + 唤醒词运行时）
```

| 组件 | 语言/框架 | 端口 | 职责 |
|------|-----------|------|------|
| **xiaozhi-server** | Python 3 + asyncio + websockets | 8000 (WS) / 8003 (HTTP) | 核心语音 AI 引擎：VAD/ASR/LLM/TTS/意图/记忆、插件与工具调用、与设备实时通信 |
| **manager-api** | Java 21 + Spring Boot 3 + MyBatis-Plus + MySQL + Redis + Shiro | 8002 | 管理后端 REST API、用户/设备/配置/音色/OTA 管理，为 xiaozhi-server 提供配置 |
| **manager-web** | Vue 2 + Element UI + Vuex + Vue Router | 8001 | 管理后台 SPA 界面 |
| **manager-mobile** | uni-app v3 + Vue 3 + Vite + pinia | — | 移动端智控台 |
| **digital-human** | Python + 原生 HTML/JS + Sherpa-ONNX | 8006 | 数字人测试页 + 本地唤醒词运行时 + 事件桥 |

**当前部署形态**：本项目 `data/.config.yaml` 中**没有** `manager-api` 配置，因此 `xiaozhi-server` 运行在**独立/最简模式**——直接读本地配置文件，**不依赖** manager-api、manager-web、MySQL、Redis。核心语音功能完全由 `main/xiaozhi-server` 单服务承担。

## 3. 语音交互完整数据流（核心主线）

```
ESP32 设备                          xiaozhi-server (Python)
   │                                        │
   │ ① 建立 WebSocket 连接 (hello 握手)       │
   │  ws://<ip>:8000/xiaozhi/v1/             │
   │--------------------------------------->│  每个连接一个 ConnectionHandler 实例
   │                                        │
   │ ② 上传音频流 (Opus 24kHz 二进制消息)     │
   │--------------------------------------->│  解码 Opus → PCM(16kHz)
   │                                        │
   │                                        │  ③ VAD (SileroVAD) 检测语音起止
   │                                        │  ④ ASR (FunASR/SenseVoiceSmall) 语音→文本
   │                                        │  ⑤ Intent (nointent) → 直接交给 LLM
   │                                        │  ⑥ LLM (glm-4-flash) 生成文本回复（流式）
   │                                        │  ⑦ TTS (EdgeTTS) 文本→语音
   │ ⑧ 语音流 (二进制消息)  <-----------------│
   │  设备播放                                 ⑨ Memory 异步保存/总结对话
```

关键点：
- **音频格式**：设备上行 `opus`，采样率 `24000`，单声道，`frame_duration=60`。服务端用 `opuslib_next` 解码为 **PCM 16kHz** 再喂给 VAD/ASR。
- **全双工实时**：每台设备一个独立的 `ConnectionHandler`（`core/connection.py`），各自维护对话上下文、VAD/ASR 状态，互不干扰。
- **流式 LLM + 流式 TTS**：LLM 边生成边送入 TTS 队列，TTS 边合成边回传，实现低延迟、支持"实时打断"。

## 4. 当前实际使用的 AI 组件（重点）

> 配置由 `config.yaml`（默认模板）与 `data/.config.yaml`（覆盖，含真实密钥）**深合并**而成（见第 8 节）。下面表格是**当前生效**的组合。

| 模块 | 当前选择（selected_module） | 底层实现 | 具体模型 / 服务 | 说明 |
|------|------|------|------|------|
| **VAD**（语音活动检测） | `SileroVAD` | `core/providers/vad/silero.py` | 本地 Silero VAD 模型 | 免费本地运行，阈值 0.5 / 低阈值 0.3，模型在 `models/snakers4_silero-vad` |
| **ASR**（语音识别） | `FunASR` | `core/providers/asr/fun_local.py` | 本地 **SenseVoiceSmall**（阿里 FunASR） | 免费本地模型，`models/SenseVoiceSmall`，语种 `auto` 自动检测（支持 zh/en/ja/ko/yue） |
| **LLM**（大模型） | `ChatGLMLLM` | `core/providers/llm/openai/openai.py`（openai 兼容接口） | **glm-4-flash**（智谱，免费） | `base_url = https://open.bigmodel.cn/api/paas/v4`，真实 `api_key` 在 `data/.config.yaml` |
| **VLLM**（视觉大模型） | `ChatGLMVLLM` | `core/providers/vllm/openai.py` | glm-4v-flash（智谱） | ⚠️ 当前 `api_key` 是占位符，**未真正启用**（视觉/拍照识别不可用） |
| **TTS**（语音合成） | `EdgeTTS` | `core/providers/tts/edge.py` | 微软 Edge 神经网络音色 **`zh-CN-XiaoyiNeural`** | 免费，联网调用微软接口 |
| **Memory**（记忆） | `mem_three_tier` | `core/providers/memory/mem_three_tier/mem_three_tier.py` | 本地"三级记忆漏斗"（见第 6 节） | 免费本地，靠 LLM 总结，数据存 `data/*.json` |
| **Intent**（意图识别） | `nointent` | `core/providers/intent/nointent/nointent.py` | 无意图识别 | 始终返回 `continue_chat`，**不启用工具调用/插件**（见第 7 节） |

**结论**：当前是一套**几乎全免费、本地优先**的入门方案——ASR/VAD 本地跑，LLM 用智谱免费 `glm-4-flash`，TTS 用微软 Edge 免费接口，记忆本地存储，意图识别关闭。

## 5. Provider 模式：如何理解/切换 AI 服务

每个 AI 能力类型都有一个**抽象基类**，具体服务是基类的实现类：

```
core/providers/
  ├─ vad/     SileroVAD（仅此一个本地实现）
  ├─ asr/     fun_local(SenseVoice) fun_server(SenseVoice-Server) sherpa_onnx_local
  │           doubao/doubao_stream(火山) tencent aliyun/aliyun_stream baidu
  │           openai(whisper) vosk xunfei_stream qwen3_asr_flash 等
  ├─ llm/     openai(通用，覆盖智谱/阿里/DeepSeek/火山…) ollama dify fastgpt
  │           gemini coze xinference homeassistant 等
  ├─ vllm/    openai（glm-4v-flash / qwen-vl 等）
  ├─ tts/     edge doubao huoshan_double_stream(火山流式) aliyun tencent cozecn
  │           fishspeech gpt_sovits_v2/v3 openai siliconflow minimax index_stream paddle_speech 等
  ├─ intent/  nointent  intent_llm  function_call
  ├─ memory/  nomem  mem_local_short  mem_three_tier  mem0ai  powermem  mem_report_only
  └─ tools/   统一工具处理器（device_iot / device_mcp / server_mcp / mcp_endpoint / server_plugins）
```

**切换方式**：只需改 `config.yaml` 的 `selected_module`（选哪个 provider），再在该 provider 的配置块里填好密钥即可。`selected_module` 决定了运行哪个实现。

**动态装配逻辑**：`core/utils/modules_initialize.py` 的 `initialize_modules()` 是工厂——根据 `selected_module.X` 和对应配置块的 `type` 字段，用 `importlib` 动态导入并实例化对应的 Provider 类。若配置块里有 `type` 用 `type`，否则直接用 `selected_module` 的名字当类名。

## 6. 记忆系统：mem_three_tier（三级记忆漏斗）

当前选的是自定义的 `mem_three_tier`，专为这个"情感导师"场景做的多用户本地记忆，按 `role_id`（= 设备 MAC，即 `device_id`）隔离：

- **第一级 · 基因记忆/人设**：即 `config.yaml` 的 `prompt` 字段，不落盘。
- **第二级 · 阶段摘要**：存 `data/summary.json`，每个 role_id 三个字段 `user_profile`（用户画像）、`relationship_stage`（关系阶段）、`recent_events`（最近事件）。由 LLM 用 `SUMMARY_PROMPT` 增量更新。
- **第三级 · 长效碎片 + 关键词召回**：存 `data/vector_memories.json`，保存不超过 200 条、每条 ≤40 字；通过内置 `KEYWORDS_MAP`（针对用户"西南风"的关键词网，如"武汉/实验室/RV1126/王者…"）做**关键词召回**，命中才注入。

触发时机：每次连接关闭时（`connection.py` 的 `_save_and_close`）异步调用 `save_memory`，用主 LLM（glm-4-flash）总结对话并增量更新摘要 + 抽取一条碎片。

## 7. 意图识别与工具调用（当前为关闭状态）

- 当前 `Intent = nointent`：`detect_intent()` 永远返回 `continue_chat`，**因此 LLM 不会拿到工具列表、不会触发任何 function call**。意味着下面第 7.2 节的插件目前**不会被执行**。
- 代码里 `_initialize_intent()`（`core/connection.py`）只有 `intent_type` 为 `function_call` 或 `intent_llm` 时才 `load_function_plugin = True` 并初始化 `UnifiedToolHandler`。

三种可选意图模式（改 `selected_module.Intent` 即可）：

| 模式 | 说明 | 优缺点 |
|------|------|--------|
| `nointent`（当前） | 不做意图识别，直接对话 | 免费、最快，但无工具/插件/退出识别 |
| `intent_llm` | 前置一个 LLM 判断意图，再决定是否调用工具 | 通用性强，但多一次串行 LLM 调用，更慢 |
| `function_call` | 让 LLM 走 OpenAI function calling，按需调用工具 | 快、效果好，但要求 LLM 支持 function calling |

> 若要启用工具调用（例如让"小雨"能查天气/播新闻/退出），把 `Intent` 改成 `function_call`，并在 `Intent.function_call.functions` 里列出要加载的插件。`core/connection.py` 的 `chat()` 中 `direct_answer` 是一个**虚拟工具**，用于把"调不调工具"的二选一变成"调哪个"的多选，防止小模型误触发真实工具。

## 7.2 插件系统（plugins_func）

插件即"技能/工具函数"，位于 `plugins_func/functions/`：

```
call_device.py            控制设备（IoT）
change_role.py            切换角色人设
get_weather.py            查天气（和风天气 API）
get_time.py               获取当前时间
get_news_from_chinanews.py / get_news_from_newsnow.py   查新闻（RSS）
play_music.py             播放本地音乐
hass_init.py / hass_state.py / hass_play_music.py       Home Assistant 智能家居
search_from_ragflow.py    知识库检索（RAGFlow）
web_search.py             联网搜索（metaso / Tavily）
handle_exit_intent.py     退出识别（再见/拜拜）
```

- 每个插件通过 `plugins_func/register.py` 注册 `Action`（函数名、描述、JSON Schema 参数）。
- `connection.py` 里 `auto_import_modules("plugins_func.functions")` 启动时扫描加载。
- 插件相关密钥/参数在 `config.yaml` 的 `plugins:` 段配置（如 `get_weather` 的 `api_key`、`default_city`；当前 `data/.config.yaml` 覆盖了天气 key 和默认城市 `重庆`）。

## 8. 配置机制（重要，别踩坑）

### 8.1 双文件合并

- `main/xiaozhi-server/config.yaml`：**默认模板**（大量 provider 配置、注释、占位密钥）。
- `main/xiaozhi-server/data/.config.yaml`：**用户覆盖配置**（只写要改的项，存真实密钥）。
- 加载逻辑（`config/config_loader.py` 的 `load_config()`）：
  1. 读 `config.yaml`（默认） + `data/.config.yaml`（自定义）。
  2. 若 `data/.config.yaml` 有 `manager-api.url` → 走智控台远程配置；**否则** → `merge_configs(default, custom)` 深合并，custom 优先级更高。
  3. 结果缓存到 `core.utils.cache`（`CacheType.CONFIG`）。

> ⚠️ 本项目的 `data/.config.yaml` 没有 `manager-api`，所以是**本地配置模式**，直接深合并 `config.yaml` + `data/.config.yaml`。**真实密钥（智谱 glm-4-flash 的 api_key、和风天气 key）存在 `data/.config.yaml`，不要外泄。**

### 8.2 实际生效的 LLM 配置

`data/.config.yaml` 只覆盖了 `LLM.ChatGLMLLM` 的 `api_key`（以及 `plugins.get_weather`）。因此合并后 `ChatGLMLLM` 实际生效的是：

- `type: openai`（来自 config.yaml）
- `model_name: glm-4-flash`（来自 config.yaml）
- `base_url: https://open.bigmodel.cn/api/paas/v4`（.config.yaml 的 `base_url` 优先于 config.yaml 的 `url`）
- `api_key: <真实密钥>`（来自 .config.yaml）

`openai.py` 的 `LLMProvider` 实际读取的键是 `model_name` / `api_key` / `base_url`（缺省回退 `url`），用官方 `openai` SDK 以流式方式请求智谱的 OpenAI 兼容接口。

### 8.3 主要运行配置（server 段）

- 监听 `0.0.0.0:8000`（WebSocket）、`http_port: 8003`（OTA + 视觉分析接口 `/mcp/vision/explain`）。
- 音频：`opus / 24000 / 1ch / frame_duration 60`。
- 无语音 120 秒后断开；TTS 超时 10s；工具调用超时 30s。
- 认证默认 `enabled: false`（开发模式，未开设备鉴权）。
- 退出命令：`退出`、`关闭`。

## 9. 系统提示词与人设

当前项目把"小智"定制成了名为 **"小雨"的情感导师/倾听者**，面向用户 **"西南风"**（一位有刻骨铭心恋情、常泡实验室的理工男）。

- **人设主体**：`config.yaml` 的 `prompt:` 字段（约 500 字的详细人设 + "运行时绝对指令"：用"她"指代前女友、禁止提名字、回复 400–600 字、富含哲理/回忆/比喻/名言、禁止 Markdown）。
- **提示词模板**：`prompt_template: agent-base-prompt.txt`，内含 `{{base_prompt}}`、`{{language}}`、`{{current_time}}`、`{{today_date}}`、`{{weather_info}}`、`{{dynamic_context}}` 等占位符。
- **提示词管理器**：`core/utils/prompt_manager.py` 负责把占位符替换为真实上下文（时间/日期/天气/设备位置），并注入声纹识别出的说话人身份等动态信息。
- **结束语**：`end_prompt` 开启，结束对话时让 LLM 以"时间过得真快"开头生成依依不舍的告别。

## 12. 给下一个 AI 的速览总结

1. **这是什么**：ESP32 语音助手的后端，核心是一个 Python 异步服务 `xiaozhi-server`，用 WebSocket 跟设备双向传音频。
2. **处理链路**：`Opus 音频 → 解码 PCM → SileroVAD 切句 → FunASR(SenseVoiceSmall) 识别 → glm-4-flash 生成回复 → EdgeTTS 合成 → 回传设备`。
3. **当前模型全览**：VAD=SileroVAD（本地）、ASR=FunASR/SenseVoiceSmall（本地）、LLM=智谱 glm-4-flash（免费 API）、VLLM=glm-4v-flash（未配 key 不可用）、TTS=微软 Edge `zh-CN-XiaoyiNeural`（免费）、Memory=mem_three_tier（本地三级记忆）、Intent=nointent（关闭工具调用）。
4. **人设**：定制为情感导师"小雨"，陪伴用户"西南风"，记忆/提示词深度绑定这个场景。
5. **配置**：`config.yaml`（默认）+ `data/.config.yaml`（覆盖，存密钥）深合并；没接 manager-api，独立运行。
6. **改模型**：改 `config.yaml` 的 `selected_module` + 对应 provider 块填 key 即可；`core/utils/modules_initialize.py` 是装配工厂。
7. **启用工具/插件**：把 `selected_module.Intent` 从 `nointent` 改为 `function_call` 并配置 `functions` 列表。
